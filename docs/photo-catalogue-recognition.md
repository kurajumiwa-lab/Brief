# Photo catalogue recognition

Vendors can open My desk → Add products from photos, upload up to four images, and explicitly consent to OpenAI analysis. The model suggests up to 12 product names and up to three optional questions per product, in the selected English or Kiswahili. The seller must select and correct each suggestion and enter stock and price; answers are saved as public offering descriptions. Manual entry still works. These are suggestions, not verified stock, prices, provenance or quantities.

The backend uses OpenAI's Chat Completions vision API. To activate it on the backend host, configure `PHOTO_VISION_API_KEY` as a secret and, optionally, `PHOTO_VISION_MODEL` (default `gpt-4o-mini`). No credential belongs in source or frontend. The feature fails clearly when unconfigured or the provider fails; configuring it may incur per-request charges. Set provider spending limits and review its data processing terms and Kenya privacy obligations before enabling. Photos are uploaded to Brief's existing public-media storage and are also sent to OpenAI only after consent; don't use private images. Input is re-encoded and metadata stripped before the provider call. The backend uses a 6-per-vendor and 60-global requests-per-minute cap, shared only if Redis is configured; otherwise it is per process. These are rate limits, not a billing quota.

Uploads and suggestions are separate: stored photos are attached to every saved offering in this flow, while raw selected files are sent for recognition. Each product save is an independent API operation; no automatic publication or generated price/quantity occurs. The API limits each request to four 8 MB images and uses the existing vendor authentication. The current model has not been benchmarked on Kenyan stock and may miss or misidentify products or produce awkward questions; seller review is essential. If a save times out, check the desk before retrying because a response can be lost after the server commits.

No provider call or production deployment was performed as part of this implementation; tests mock the external provider. The runtime host must have outbound access to `api.openai.com`, a configured key, and a deployed version of this branch before recognition works.

## Text and provider choice

The seller can describe goods with or without photos and choose OpenAI or Google Gemini in the Brief interface. Changing providers resets consent. Gemini uses `GEMINI_CATALOGUE_API_KEY` and optionally `GEMINI_CATALOGUE_MODEL` (default `gemini-2.5-flash`), with outbound access to `generativelanguage.googleapis.com`. The key is server-side only. Configure spending limits and assess the selected provider's data handling terms: Gemini's free tier may use submitted content to improve Google products. Uploaded photos are public by link regardless of whether AI analysis is requested. Both providers share the existing request rate limits. Tests simulate responses; neither live Gemini nor OpenAI has been validated in this environment. This is Gemini API support inside Brief, not an integration into the consumer Gemini or ChatGPT apps.

A saved product can be shared through an editable caption and public product link on WhatsApp, or copied for manual posting elsewhere. TikTok direct publishing and ChatGPT/MCP account linking are not implemented. The public page shows only active visible goods; purchase requests still require sign-in. Order downloads are transaction records, not eTIMS tax invoices or evidence of payment.
