# General marketing campaigns

A signed-in member can post a public-to-members brief with location, budget and deliverables without an event. Other members can submit one private KES offer, withdraw it while open, and revisit it under My offers. The campaign owner can review offers, message a creator through existing direct chat, accept one offer, or close the campaign. Accepting closes the campaign; this records a selection only. There is no escrow, platform payment, guaranteed reach, identity/reach verification, delivery tracking, dispute mechanism, editing or notification of offers in this first version. Both parties must arrange details directly. Briefs are visible to signed-in members; offers are visible to the campaign owner and offer author. Avoid including sensitive information in briefs.

Deployment requires Alembic revision `0087_marketing_campaigns` before deploying the API. New tables have RLS enabled without public API policies; the application database role must be authorized to access them. Do not expose them through a service role to untrusted clients. Existing chat privacy is a separate deployment concern: prior inspection found RLS disabled and anon SELECT grants on Brief2 chat tables; exposed API reachability has not been verified. Resolve that risk before relying on chat for sensitive communications.

This does not implement ChatGPT/MCP account linking or TikTok OAuth/direct posting. Those need separate authenticated integrations, secure token handling, consent, provider app configuration and (for TikTok) required access/approval and publishing-policy review.
